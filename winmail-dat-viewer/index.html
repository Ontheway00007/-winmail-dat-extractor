Winmail.dat viewer and opener

Before you download anything, it helps to see what a winmail.dat file actually contains. This page explains how to list the contents of a TNEF container in your browser and how to evaluate the many winmail.dat openers competing for your file.

By the Winmail.dat Extractor team·5 min read

Why viewing before extracting is useful

A winmail.dat file gives you no hint about its contents. Two containers of similar size can hold a signed contract or nothing but Rich Text formatting. Listing the contents first tells you three things immediately:

  • Whether real files exist. If the list is empty, no converter on the internet will do better, and the correct next step is to contact the sender.
  • Whether the filenames match expectations. An unexpected .exe, .js, .iso or macro-enabled Office file is a reason to stop and verify with the sender.
  • Whether anything is missing. If a colleague mentioned five documents and the viewer lists two, the rest may have been sent by reference or stripped by a gateway.

The viewer on this site lists names and sizes as soon as the container is parsed, and only builds a ZIP when you ask for one.

How a browser-based viewer works

The tool reads the file with the browser File API, checks the four-byte TNEF signature, then walks the attribute stream. Attachment-level attributes carry the display name, the transport filename and the raw bytes. The viewer decodes the names (handling both Windows-1252 and UTF-16 encodings), removes characters that are illegal in filenames, de-duplicates repeated names and reports the byte count of each payload.

Because all of that is plain JavaScript, the container never leaves your device, and the page keeps working with the network disconnected. That is a meaningful difference from server-side converters, which necessarily receive a copy of your email attachment.

How to judge any winmail.dat opener

Search results are full of winmail.dat openers. A short checklist separates the trustworthy ones:

Where is the file processed?In the browser, with a clear statement that no upload happens
What happens to uploads?If uploads are required, a published retention and deletion policy
Is there an email or sign-up wall?No. Extraction should not require an account
Are limits disclosed?Yes, including which TNEF object types are unsupported

Are the results honest?An empty container produces a clear message, not a broken download
Confidential documents: if the attachment contains legal, medical, financial or HR material, avoid any tool that uploads it. Client-side extraction or a desktop tool keeps custody of the data with you.

Desktop and email-client alternatives

A browser viewer is the quickest route, but there are other legitimate paths:

  • Outlook itself. Opening the message in any version of Outlook, including Outlook on the web with a Microsoft 365 mailbox, usually resolves the container invisibly.
  • Forward the message. Forwarding to a colleague who uses Outlook lets them save the attachments and send them back as ordinary files.
  • Command-line tools. On Linux and macOS, the classic tnef utility unpacks containers from a terminal, which suits scripted or batch recovery.
  • Ask for a resend. The most reliable fix, and the only one that also prevents the next occurrence.

Frequently asked questions

Can I view winmail.dat without downloading anything?

Yes. A browser-based viewer lists the attachment names and sizes as soon as it parses the container, so you can inspect the contents and only then decide whether to save the ZIP.

Is there a winmail.dat viewer for iPhone?

The browser viewer works in Safari on iPhone and iPad, so no App Store download is needed. Save the attachment to Files first, then select it in the viewer.

Why does the viewer show a file with no name?

Some senders omit the display name and transport name attributes. The viewer then assigns a placeholder such as attachment-1, and you can rename it after extraction based on the file type.

Can a viewer show the message text inside winmail.dat?

The message body is stored as compressed RTF rather than as an attachment, so an attachment viewer will not display it. The readable text usually arrived in the email itself.

Does the viewer work with .dat files that are not TNEF?

No. If the signature check fails, the file is a different kind of .dat file, such as a database or game data file, and needs the application that created it.
